# Server authority: writer and lock inventory

This is the writer inventory for the current uncommitted implementation, not completed acceptance. `module-control.ts` owns scoped grants, native enrollment, module settings and admission. Native publication, observations, server dispatch and encrypted escrow extend that same boundary. Protected client execution and complete concurrent PostgreSQL verification remain pending. See [the implementation boundary](server-module-authority.md).

## Proposed common order

Within a transaction that can change or admit work: runtime custody; management scopes and their grants sorted by stable ID; module state sorted by scope and module ID; devices sorted by ID; native enrollments and exact credentials sorted by ID; publication intent/head; batch and job rows sorted by ID; then audit and terminal receipts. Treat this as a migration target, not the order of existing handlers. Discovery before the locks is only a locator and must be checked again under the locks. Locks protect authority until the result is committed; an early authenticated identity is not a substitute for rechecking expiry, revocation and bindings.

The new owner uses a shared runtime lock and exclusive scope fences. Scope fences protect grant/module reads as well as writes. Command creation/approval locks all discovered scopes, then devices, then native enrollments before existing batch work. Invitation redemption also locks the invitation under its immutable scope fence and rechecks expiry when consuming it. Native rotation and lineage revocation serialize under that scope and device. Integration admission holds the scope until all abortable adapter work finishes. Legacy writers have not all been migrated; they must not acquire new scope locks after their existing device or batch locks. The legacy agent path excludes native credentials, and legacy ring/revoke paths reject native devices.

Long-lived publication signing operates outside these locks after immutable intent capture. Finalization reacquires the common locks and compares authorization, deadlines and head. Freshness issuance uses the common locks through its bounded signer call and commit. A timed-out or abandoned signer cannot publish. No response leaves before commit. An indeterminate commit is reconciled; it is not replayed automatically.

## Current writers to migrate

| Existing entry point | Present writes and relevant locks | Required authority work |
| --- | --- | --- |
| Enrollment and redemption | Native invitations bind scope/device/platform/machine and inviter; redemption fences runtime/scope, validates the live inviter grant, locks the device/enrollment/exact credential and consumes the invitation. The console creates explicit native invitations. | Verify concurrent redemption, expiry and unknown outcomes. Legacy tokens do not establish native authority. |
| Credential rotation | Legacy rotation locks device/exact credential. Dedicated native rotation additionally locks custody, scope and enrollment and preserves its lineage; native enrollment revocation revokes all linked credentials. | Verify native rotation/revocation ordering with independent PostgreSQL connections. Individual legacy credential revocation still does not revoke replacements. |
| Device ring and revocation | Native routes fence runtime/scope before device/enrollment; ring changes require current scope version and no unfinished jobs. Revocation covers the credential lineage. Legacy mutation rejects native targets. | Verify independent-connection races and uncertain terminal outcomes. |
| Heartbeat and inventory | Native credentials, signed current policy and enabled server modules precede sequence receipts and observations. Inventory additionally requires selected version and permission. Legacy inventory remains ignored. | Verify lost acknowledgments, replaced policy and restored counters with actual transport and PostgreSQL. |
| Batch creation | New owner checks custody, sorted scopes/grants/modules, devices and live enrollment before the existing idempotency, batch/job and audit writes. | Prove complete concurrent ordering, grant/module revocation and unknown-commit behavior. |
| Batch approval and cancellation | Approval enters the common scope/device/enrollment boundary before batch writes; cancellation acquires discovered scope fences before batch/job writes. Native admission stores creator and independent approver issuer/subject. | Verify changed target bindings, approval digests and concurrent disable. |
| Native claim | Current policy and native credential acquire common locks before job selection. Creator/approver grants and command permissions remain live. Claim UUID, token hash and exact response are committed together. | Implement protected client command execution and verify claim races. Unknown/restored work must never replay. |
| Native lease renewal | Repeats current policy/module/grant and exact credential admission. Lease expiry is capped by policy, maintenance window and the bounded lease. | Verify concurrent grant revoke, module disable, expiry and terminal evidence. |
| Native terminal report | Live credential/common scope fence precedes job/claim receipt. Module disable does not prevent evidence receipt; late evidence is retained with reconciliation required and cannot renew execution. | Verify exact duplicate/conflicting terminal receipts and late outcomes. |
| Job reconciliation | Locates job, locks device, updates indeterminate job and records audit. | Keep authorized terminal reconciliation available under scope and common lock order; never replay restored work. |
| Expired-job coordinator | Runtime and sorted native scope fences precede sorted device locks with skip-locked. Expired work terminates without automatic read-job requeue. | Verify overlap with dispatch, cancellation and restoration. |
| Release publication | Inserts signed legacy release and audit. | Keep its existing format separate from native publisher evidence and catalog/policy/freshness signing roles. Protect any optional admission with scope and authority. |
| Falcon/EMA, sync and events | Configured scope, grant/module admission and bounded adapter work share the fence. Falcon scheduler requires explicit scope/interval/module configuration. Authenticated HMAC events commit exact receipts. | Real provider contracts and concurrent disable verification remain pending. |
| Local backup restore | Inventories cover v1-v9. Isolated PGlite restore quarantines authority/publications/nonce/claim records, clears heads, revokes credentials/enrollments/grants, disables modules and preserves encrypted escrow/history. | Current populated-fixture acceptance and isolated real PostgreSQL restore remain open. |
| Module configuration and native publication | Server settings use version CAS and selected roots; disable cancels queued work and preserves leased uncertainty. Catalog/policy signing freezes intent outside locks and finalizes under common fences. Freshness holds the fence through bounded signing and receipt commit. | Verify current migration/runtime races, signer timeouts, exact receipt retries and authority recovery. |
| Recovery-key escrow/reveal | Upload requires live enrollment/current policy, selected BitLocker permission, enabled escrow and effective backup setting. AES-GCM encrypted rows bind immutable identity. Reveal requires owner/reveal grant, verified recent MFA and audited commit before returning plaintext. | Protected keyring custody, real policy/endpoint upload and audit/step-up acceptance remain open. |

Legacy claim/report retain device-first ordering and exclude native credentials. The native server paths are present; protected client command execution is not connected. Each writer and the terminal coordinator still require barrier-controlled PostgreSQL race coverage before the admission boundary is called complete. Compiler success alone does not establish locking or transaction correctness.
