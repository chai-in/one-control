# Bounded native wake packet sender

`native/internal/wake` is a stateless packet component for a future optional Ubuntu relay module. It has no listener, command protocol, service installer, polling loop, or bootstrap integration. The active relay remains unbuilt. This package does not authorize a wake or prove that a computer woke.

`Send(ctx, Site, Target)` accepts configuration values. `Site` contains an exact site ID, interface name, literal source IPv4 address, and canonical subnet prefix. `Target` contains the same exact site ID and a MAC address. Site equality checks configuration consistency only. The caller must supply a nonnil context.

The MAC has exactly six two-digit hexadecimal octets separated by colons. Hexadecimal letters may use either case. The sender rejects zero, broadcast, multicast, whitespace, other separators, compact addresses, and EUI-64. Locally administered unicast addresses are valid.

The subnet must contain usable host addresses and lie wholly within one RFC1918 block. The source must be a native IPv4 host within that subnet. The sender rejects mapped IPv6, public, loopback, link-local, multicast, unspecified, subnet, and directed-broadcast source addresses. It rejects noncanonical prefixes and prefixes longer than 30 bits. It derives the sole directed-broadcast destination and always uses UDP port 9. Callers cannot supply a payload, destination, port, count, retry rule, or interval.

The exact named OS interface must be up and broadcast capable. It must have the source address with the exact prefix length. Loopback and point-to-point interfaces are rejected. The sender snapshots the index, name, and flags, then rechecks that identity, flags, and address before every write. It performs no interface discovery or fallback.

Each call binds one connected `udp4` socket to the exact source and an ephemeral local port. A successful call submits three identical 102-byte magic packets with 100 ms cancellable gaps. Each packet contains six `FF` bytes followed by sixteen copies of the target MAC, following [AMD's Magic Packet Technology white paper](https://www.amd.com/content/dam/amd/en/documents/archived-tech-docs/white-papers/20213.pdf), page 2. The socket and wait budget is one second, clamped to an earlier caller deadline. Published deadlines are checked even if context cancellation notification is pending. The socket receives a write deadline. Cancellation closes the socket, and the sender stops or joins that close callback before returning. [Go's DialContext documentation](https://pkg.go.dev/net#Dialer.DialContext) states that cancellation after connection does not affect the socket.

`Report.Attempts` is a fixed three-element array. Its zero value is `NotAttempted`. `LocalKernelAccepted` means a full write returned without error. `UnknownWrite` means a started write returned an error or a wrong byte count. An unknown write stops the call without retry. Prior accepted outcomes remain accepted if a later cancellation or interface change stops the call. No result proves physical transmission, target power state, authenticated contact, or RDP readiness.

Synchronous OS interface queries cannot be interrupted by the caller context. They may delay return beyond the socket and wait budget. The sender checks cancellation and deadline after each query rather than leaving a background query goroutine. Source binding and repeated checks do not establish kernel interface pinning, exclusive egress, VLAN isolation, or site trust. Interface state can still change after a check. This unit has no privileged helper, `SO_BINDTODEVICE`, or Linux host containment.

The future relay owner must enforce authenticated relay and owner identity, current policy, an exact approved target and site mapping, request expiry, durable deduplication, and rate limits before calling this package. It must persist intent and uncertain outcomes according to the existing authority model. Restored or uncertain mutations must never be replayed automatically. A plain `Site` or `Target` value supplies none of that authority. This package defines no competing wire protocol.

Tests use fictional network configuration and a private adapter defined only in `_test.go`. That adapter checks the selected fictional source, derived broadcast, and fixed port before opening an actual socket on `127.0.0.1` with ephemeral ports. Production `Send` always uses actual OS lookup and the production dialer. There is no exported fixture mechanism or environment bypass.

Actual loopback captures check every packet byte independently, exactly three packets, no extras, invalid-input silence, cancellation, earlier deadlines, and interface-change stops. Separate synthetic fault tests check unknown writes and cancellation of a blocked writer. Those synthetic tests do not prove actual kernel write blocking. Linux cross-compilation does not prove runtime interface behavior or privileges.

Actual Linux egress, privileges, overlapping routes, selected-module installation, service containment, authenticated request integration, physical wake, long shutdown and sleep behavior, relay restart, and subsequent Windows contact and RDP readiness remain acceptance gates. Focused tests do not replace the coordinator's integrated checks or a real-machine pilot.
