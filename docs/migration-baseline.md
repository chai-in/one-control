# Frozen v1 catalog admission

`inspectFrozenV1` is a read-only preparation component for a later ordered migration runner. It returns `empty`, `compatible` with `catalog-v1` admission and a descriptor digest, or `incompatible` with a fixed category. It executes no DDL, writes no history, and grants no migration authority. Database transport failures retain their original failure.

The caller owns a single transaction, an explicitly selected database and authenticated migrator identity, exclusive managed-schema DDL authority, and an offline maintenance window with old and runtime binaries stopped. Before inspection it takes advisory transaction lock `748391234`, then the existing nine baseline tables in sorted `ACCESS EXCLUSIVE` order. The caller supplies the exact namespace and sets its transaction-local search path to that namespace followed by `pg_catalog`. It repeats admission before assigning any future history identity. Table and advisory locks do not exclude privileged unrelated DDL.

`frozen-v1.ts` preserves twelve complete statements, their boundary whitespace, the original Git blob, source-file and exported-string SHA-256 identities, and a versioned migration checksum. `schema.ts` stays unchanged. The reader compares a fixed source-owned catalog descriptor. Its digest records observed logical compatibility, never proof that the original database executed the frozen source bytes. Unsupported engine representations are rejected. The declared representations are PostgreSQL 18.6 and lockfile-pinned PGlite 0.5.9.

The descriptor covers all namespace relations, ordered and dropped attributes, types and defaults, CHECK and foreign-key enforcement, indexes and partial predicates, sequence ownership, internal trigger enforcement, generated row and array types, and unexpected namespace object families. A raw-catalog preflight rejects user-defined type and routine dependencies before expression deparsing. Namespace names are represented explicitly in generated type metadata. Index keys, predicates, access methods, operator classes and collations are compared as separate catalog fields. No arbitrary SQL definition is rewritten. Result groups have a fixed 128-row bound and the returned descriptor has a 128 KiB bound. The qualified historical marker must contain exactly version 1. Empty means no managed objects.

The test fixture has a closed `empty` or `frozen-v1` mode. It retains the accepted owned-run custody checks, fresh minted roles and namespaces, restricted runtime grants, exact identity checks, connection ownership and cleanup. Its migrator callback never accepts a target URL or exports credentials. Existing fixture behavior stays the default. A separate REPEATABLE READ, READ ONLY runtime probe proves the reader's SQL works without mutation permission. That observation grants no migration or history-admission authority.

Expected PGlite catalog provenance is retained in `tests/fixtures/frozen-v1-catalog/pglite.json`. It was created in an independent fresh engine by the unchanged exported source, before admission tests. Tests do not regenerate expected catalogs. Required PostgreSQL evidence records frozen-source admission and empty-state acceptance, structural and marker denials, independent before and after observations, representative row preservation, locks, runtime DDL and history-write denial, and exact fixture cleanup. The runner requires the eighth suite and complete allowlisted observations.

The later unit must implement the ordered transactional history, consistent compatibility readiness, and deliberate backup-v2 and frozen-v1 restore using the existing transaction owner. Current migration behavior, readiness and backup format are unchanged here. Local engine admission establishes no production grant, deployment, backup, PITR or recovery claim.
